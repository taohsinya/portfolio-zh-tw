# 用模擬使用者做測試

AI 可以在幾分鐘內扮演幾百個使用者。這讓它成為上線前測試產品的強大工具，但也很容易讓人自欺欺人。這一頁說明我怎麼使用它，以及如何讓它保持誠實。

## 三輪檢驗

```
第 1 輪 · 紙上評估
  用模擬使用者為規格評分（預期 NPS 必須為正）
    ↓
第 2 輪 · 模擬行為
  模擬使用者實際走過 Beta 版產品，記錄他們點了哪裡、在哪裡流失
    ↓
第 3 輪 · 正式上線
  與真實使用者數據比對
    ↓
檢討落差 → 調整模擬 → 重複
```

目標：在寫完規格時，就能大致預測一個功能的表現。

## 為什麼 AI 模擬太樂觀

AI 模擬是**必要的，但不夠**：

- **如果模擬分數是負的 → 強烈訊號。** 真實使用者只會更不滿意。退回重做。
- **如果模擬分數是正的 → 微弱訊號。** 只能證明這個點子在紙上說得通。

它有三個先天偏誤：
1. **太好說話。** AI 傾向給出合理的回答，不會模擬心情不好、直接關掉 App 的人。
2. **看不到摩擦。** 載入時間、分心、付錢時的心痛，都不在模擬裡。
3. **太理性。** AI 不會模擬不理性的決定。

我的經驗法則：**模擬結果為正時，打個折，只算模擬值的 50–70%**。

## 用真實數據修正模擬

兩個模擬與現實不一致的例子，以及我們的處理方式：

- **起始分數太負面。** 第一次模擬把起始 NPS 設在 −100：每個模擬使用者都不滿意。但真實的試用數據顯示，很多使用者至少滿意到願意試用付費方案，所以一位同事把基準修正為 −50。教訓：用你手上已有的真實數據來校準模擬。
- **模擬高估了入口、低估了核心。** 它認為歡迎畫面的影響比主要分析頁面還大。經過審查後，主要分析頁面成為單一最大的貢獻來源，歡迎畫面的排名則下降。教訓：要檢查排名合不合理，不只看總分。

最終的模擬 NPS 會乘上 0.8 作為固定修正，之後再與一個根據真實使用者行為建立的 NPS 估算值比對；這個估算值是數據團隊從使用紀錄建立的。

## 同樣的數據，不同的呈現

這些測試得出一條設計原則：**每個人看到的數據都一樣，只有呈現方式不同。** 快速瀏覽的讀者和深入研究的讀者看到的是同樣的分數，但一個看到簡短摘要，另一個看到所有圖表全部展開。同一檔股票，只要依使用者類型調整呈現方式，模擬 NPS 就從 0 提升到 60。

## 實例

**[財務健康分數](../financial-fitness-score/README.md)**：在單一模型上走完整個循環。35 位模擬使用者 → 一個扮演挑剔財務規劃師的 AI 給第一版打了 5.5/10 → 三項修正 → 重新評分。
