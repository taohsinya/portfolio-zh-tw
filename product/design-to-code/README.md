# 從設計到程式碼：Claude Design → Figma → 程式碼

這是我為團隊制定的產品流程。它做到兩件事：

1. **點子很快變成可運作的程式碼。** 一個點子幾小時內就能變成可點擊的原型，而不是幾週，所以我們能嘗試更多點子，並及早淘汰不好的。
2. **問題在設計階段就被抓出來。** 工程和營運團隊可以在任何人寫正式程式碼之前先檢查設計，而不是做完之後才發現問題。

## 流程

```
點子
  ↓  Claude Design：依照產品的設計規範，把點子變成可點擊的原型
原型
  ↓  審查：產品、工程和營運團隊檢查（AI 審查者也會提出挑戰）
Figma
  ↓  設計團隊把核准的原型做成最終設計稿
Figma 轉程式碼
  ↓  工程師依最終設計稿開發，直接把設計稿讀進程式碼
上線功能
```

## 為什麼有效

**原型使用真正的設計規範。** 負責製作原型的 AI 會拿到產品的設計系統：顏色、間距、元件、每個畫面狀態（空白、載入中、錯誤），以及畫面上的文字該怎麼寫。所以原型一開始就長得像、用起來也像真正的產品，轉到 Figma 的距離很小。

**工程團隊及早檢查。** 因為原型很具體，負責開發和營運的人可以在任何正式程式碼存在之前就說「這行不通」。修改設計只要幾分鐘；修改已上線的程式碼要花好幾天。

**每一步都交付具體的東西。** 點子 → 原型，原型 → 審查過的設計，設計 → 程式碼。沒有任何一步是從零開始。

## 工具

兩套指令集（「skills」），教 AI 在產品設計系統內製作原型。品牌名稱、顏色和產品細節都已替換為 `{Product}` 之類的佔位符。

| Skill | 用途 |
|---|---|
| [UI 原型 skill](skills/ui-prototype-skill/) | 根據描述製作可點擊原型，內含設計系統、一個註冊流程範例，以及虛構的範例資料 |
| [產品設計系統 skill](skills/product-design-system-skill/) | 完整的設計系統、畫面生成規則、網站設計，以及介面文字撰寫規則 |
