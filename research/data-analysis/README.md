# 市場數據監測與訊號檢驗

這是我在 2026 年寫的一組小程式，透過**交易所公開資料**追蹤亞洲股市（主要是台股和韓股），以及我用來檢驗某個訊號是否真的有預測力的方法。

重點不在程式本身，而在背後的習慣：每天蒐集硬數據、在看數字之前先寫下每個數字代表什麼意義，並且檢驗說法，而不是直接相信。下面幾個最有用的結果，正是數據證明我先前判讀錯誤的案例。

> **非投資建議。** 這是研究工具和方法說明。內容不構成任何買進或賣出的建議，也不反映任何個人持倉。

---

## 各監測程式追蹤什麼

先說明幾個名詞：
- **買超／賣超：** 某類投資人當天買進股數減去賣出股數。
- **未平倉量（OI）：** 當天收盤時仍未平倉的期貨或選擇權口數。某類投資人的「淨未平倉量」是多單口數減空單口數。
- **融資：** 投資人向券商借錢買股票。這是衡量散戶槓桿最直接的指標。

| 監測程式 | 追蹤內容 | 為什麼重要（一句話） | 資料 |
|---|---|---|---|
| **三大法人買賣超** | 外資、投信和自營商每日在台股的買賣超 | 外資是台股最大的邊際買家，所以從賣超轉為買超（或反過來）常代表市場情緒轉折。 | 臺灣證券交易所（證交所 TWSE），公開資料 |
| **融資餘額** | 用借來的錢買台股的總金額，以及每日變化 | 快速上升代表市場靠借錢在撐；急劇下降通常代表斷頭賣壓。 | 證交所，公開資料 |
| **融資流向** | 當天新增的融資資金流進哪些個股、哪些市值級距和題材 | 可看出槓桿是否擴散到小型、投機性的股票，這通常發生在行情後段。 | 證交所與櫃買中心（TPEx），公開資料 |
| **期貨部位** | 外資在台指期和台指選擇權的淨部位，以及散戶在小台指期的淨部位 | 可看出大型參與者在「檯面下」如何避險或布局，這是現貨市場的買賣超看不到的。 | 臺灣期貨交易所（期交所 TAIFEX），公開資料 |
| **韓國槓桿溫度計** | 取自某個公開儀表板的韓國散戶槓桿綜合指標（網站以「泡菜溢價」命名，也就是韓國價格和國際價格之間的差距） | 韓國散戶槓桿用得很重，一旦去槓桿就會牽動整個市場，記憶體股尤其明顯。 | 第三方公開儀表板 |
| **資本支出 vs 記憶體** | 記憶體和半導體 ETF 的流通單位數，以及一個追蹤大型科技公司資料中心支出（「hyperscaler capex」，超大規模雲端業者資本支出）的公開儀表板是否有新數字 | 記憶體晶片（DRAM）價格取決於最大型雲端公司在資料中心上花多少錢，而 ETF 單位數可看出資金是進場還是離場。 | 公開網頁 |
| **SK 海力士庫藏股** | SK 海力士已公告庫藏股的每日執行進度與計畫對照（已買股數、速度、買進價格） | 股價下跌時庫藏股買得變慢，比公告的總金額更能看出公司的信心。 | 韓國交易所公告，經由第三方網站取得 |
| **因子檢驗（IC）** | 外資今天買的股票，接下來幾天是否表現優於其他股票 | 把「外資買賣有意義」從一種信念，變成一個可以通過或不通過的數字。 | 證交所，公開資料 |

為什麼看 ETF 的**單位數**而不是**資產規模**：總資產每天都會隨價格變動，所以看不出投資人有沒有加碼。流通單位數只有在資金真正進出時才會改變。

## 各部分如何串接

```
公開資料  →  檢查  →  警示／摘要  →  筆記
```

1. **資料。** 每個監測程式在收盤後下載一份公開資料，並附加到歷史檔（CSV）。保留歷史，是為了讓每個讀數都能和過去比較。
2. **檢查。** 程式把今天的數字和上一次讀數、歷史資料比較，並輸出一行 `STATUS=`，例如 `TWSE_FOREIGN_FLIP` 或 `TWSE_OK`。什麼算異常的規則寫在程式裡，不是看到數字後才決定。
3. **警示／摘要。** 一個排程執行的 AI agent（Claude Code）每天跑這些監測程式，只有在狀態顯示有變化時才通知我。另外有一條自動化流程，每天讀取券商研究報告並寫成摘要。每份摘要產出後，agent 會用硬數據核對：某個說法是不是建立在分析師的預估上，但交易所其實已經有實際數字了？
4. **筆記。** 重要的讀數會存進 Obsidian 筆記庫（一款可互相連結的筆記軟體），分成*證據*、*訊號*（各有期限）和*論點*（各有一條寫好的、能證明它錯誤的條件）。筆記庫有一條固定規則：不放個人持倉，也不放買賣建議。

## 本資料夾中的程式

這四支程式只使用交易所公開資料，不需要 API 金鑰，而且已把本機專用路徑替換掉：輸出會寫到環境變數 `MONITOR_DATA_DIR` 指定的資料夾（預設為目前資料夾）。只用 Python 3 標準函式庫。

**[`scripts/twse_flow_monitor.sh`](scripts/twse_flow_monitor.sh)** 下載證交所每日的外資、投信和自營商買賣超彙總。它會保留前一次讀數，並在兩種情況下發出警示：外資從賣超轉買超（或反過來）且當天金額超過新台幣 200 億元，或任何一天金額超過新台幣 1,000 億元。它也會把每天的數據附加到歷史檔。這是後來加上的，因為我發現第一版只保留最新一天，已經悄悄遺失了好幾天的資料。

**[`scripts/twse_margin_monitor.py`](scripts/twse_margin_monitor.py)** 追蹤融資餘額總額（借錢買股的金額）和融券餘額。它可以回補任意日期區間，之後每天執行，即使遇到假日也能抓到最新公布的那一天。最麻煩的部分是找出交易所表格中哪一欄才是今天的餘額；程式用簡單的算式來核對（昨日餘額 + 融資買進 − 融資賣出 − 現金償還 = 今日餘額）。

**[`scripts/taifex_positioning.py`](scripts/taifex_positioning.py)** 抓取外資在期貨和選擇權的淨部位，並推算散戶在小台指期的淨部位（因為市場多空總和為零，散戶部位就是法人部位總和的負值）。它能處理交易所較舊的中文編碼（Big5），每次請求可抓一整年。輸出結果已經手動和某家券商公布的每日彙總核對過。公開版本會同時拿今天的讀數和**最近 60 天**與**完整歷史**比較，原因見〈心得〉。

**[`scripts/twse_cross_sectional_ic.py`](scripts/twse_cross_sectional_ic.py)** 是因子檢驗。每個交易日，它先把流動性足夠的台股依外資買超（占當天成交量的比例）排序，再依接下來 1 到 20 天的報酬排序，然後衡量兩個排序的吻合程度。先在一段期間跑一次找出訊號，再到之後的期間跑一次，確認它仍然有效。方法說明請見 [factor-testing-method.md](factor-testing-method.md)。

## 心得

**1. 檢驗說法，而且要用對層次。** 原本的信念是「外資知道些什麼」。用整體市場的總買賣超對照大盤，以及逐檔個股分開檢驗，結果都只是雜訊。改成*跨個股*比較（外資買了哪些，而不是外資有沒有買），結果就明顯顯著。同樣的資訊，看你問什麼問題，可能看起來毫無用處，也可能很有用。

**2. 通過一次不算通過。** 外資買賣超因子在 2025 年到 2026 年中的數據上輕鬆通過。但在之後三個月卻失效了，第一個月甚至正負號反轉。我把它降級為「檢討中」，並訂下規則：每月重跑一次，連續兩個月為正才恢復。完整數字（全部是公開資料）請見[方法說明](factor-testing-method.md)。

**3. 「極端」取決於你拿什麼比較。** 期貨監測程式原本是用全部歷史資料來算百分位。2026 年 9 月的某一天，同樣的外資空單部位，在完整 647 天歷史中位於第 **4.8** 百分位，但在最近 60 天中位於第 **51.7** 百分位。「空單異常多」對照 2024–25 年是對的，對照目前的市場狀態卻是錯的。程式現在兩個都會輸出，並把 60 天的數字放在前面。

**4. 水位不等於變化。** 外資空單*最多*的日子，之後市場並沒有走弱；外資*大幅加空*的日子，之後市場才走弱（樣本小：33 天，只能當方向性證據）。這是兩個不同的問題，需要分開檢驗。

**5. 把綜合指標拆開來看。** 韓國槓桿綜合指標觸及最高警戒等級時，我把它拆成各個組成部分。結果很大一部分的變動來自一個本來就設計成有落後性的 ETF 調整項，而不是新增的借款。現在監測程式一定會把單純的借款比率和綜合指標並列輸出。

**6. 要知道數字是不是最終值。** 交易所會在當天晚上修正部分當日數字。下午 3 點和晚上 9 點抓到的讀數可能不同。每一筆歷史紀錄都應該記下抓取時間。

**7. 弄清楚一個數字能說明什麼、不能說明什麼。** 以庫藏股來說，平均買進價和收盤價的比較，看起來像是在衡量紀律，其實不是：一個穩定買進的買家，在上漲日會買在收盤價以下，在下跌日則會買在收盤價以上。真正的檢驗是：公司在下跌日是否仍買進相同的數量。

**8. 監測程式會無聲無息地失效。** 排程工作可能停了都沒人發現。現在每個工作在重新啟動後都會點名確認，而且每支程式都保留歷史檔，而不是覆寫單一狀態檔。
