# Stock 360：讓 LLM 產出機構等級個股研究的方法

這是一份約 10,000 token 的 prompt（給 AI 模型的指令），能把大型語言模型（LLM）變成一位守紀律、類似券商研究部（sell side）的分析師。只要輸入公司名稱和股票代號，它就會產出一份完整的研究報告，而且每次的架構、會計規則和評價邏輯都一致。

這套方法是我為一個 AI 投資產品設計的，並用它產出、驗證了約 90 份報告，涵蓋 14 個以上的產業。放在這裡，是想展示我如何為 LLM 設計分析系統。

> **非投資建議。** 這是一套研究方法，不是任何買進或賣出的建議。

---

## 要解決的問題

如果你請 LLM「分析一下 NVIDIA」，每次拿到的報告都不一樣：指標不同、GAAP 與非 GAAP 數字混用、同業隨機挑選，目標價也沒說明怎麼算出來。聊天時這樣沒關係，但如果是一個產品，成千上萬份報告必須能互相比較，這樣就不能用。

這套方法在分析師動筆之前，就先把它的行為規範好。

## 設計方式

### 1. 全域規則，只講一次
適用於每個章節的規則，讓模型不必用猜的：
- **評價：** 預設採用 GAAP（一般公認會計原則）；可以用預估數字，但要標明；只有在非 GAAP 數字差距超過 10% 時才使用，而且必須解釋差異來源（股份基礎薪酬、重組、減損）。
- **比較：** 每個指標都要和自身 5 年歷史、3–5 家具名同業，以及產業中位數比較。
- **EPS、利潤率、營收：** 一律使用稀釋後 EPS；利潤率採 GAAP，若股份基礎薪酬超過營收 5% 就要標註；營收成長拆成帳面、固定匯率和有機成長三種。
- **自由現金流與多事業體公司：** 自由現金流（FCF）只用一種定義；集團型公司則套用分部加總評價（sum-of-the-parts）的規則。

### 2. 產業框架，按需放入
共有 17 套產業分析手冊（銀行、保險、半導體、SaaS、生技、REITs、能源、尚無營收的公司等）。每套都定義了該產業的重點、該用哪些 KPI，以及哪些評價方法該用、哪些**不該**用。例如尚未獲利的生技公司，要用研發管線經風險調整後的淨現值（NPV）來評價，絕不用本益比（P/E）。

實際執行時，只放入相關的 1–2 套框架，讓 prompt 從約 10,000 token 縮減到約 7,000 token，也讓模型專注在正確的角度。

### 3. 固定的六段式報告
1. **公司概況與產業：** 事業部門、競爭格局、市場規模、經營團隊過往表現
2. **財務與成長：** 最新財報、營收品質、評價、利潤率、現金流、資產負債表、盈餘品質、風險與催化劑
3. **競爭護城河：** 優勢來源與資本配置
4. **動能與投資人信心：** 相對強弱、成交量、風險調整後動能
5. **市場敘事與分析師看法**
6. **評價情境：** 樂觀、基本、悲觀和災難四種情境，每種都要寫明評價方法、關鍵假設和機率；四個機率加總必須等於 100%

每個小節結尾都有一到兩句的 **Subsection Thesis（小節結論）**，讓讀者（或另一個 AI agent）能快速掃過重點。

### 4. 為檢索而設計的輸出
報告只用段落和條列，不用表格，因為報告會餵進一個檢索式（RAG）知識庫，而表格轉成向量後會失去結構。風險、催化劑和評價情境都用固定模板（`EVENT BLOCK`、`VALUATION SCENARIO BLOCK`），方便程式解析。

## 值得一提的設計選擇
- **強迫模型在評價上寫出計算過程。** 目標價必須說明算法，例如「35 倍預估本益比 × FY26 EPS 25.8 美元」，不能只給一個數字。
- **機率以 5% 為一級。** 用較粗的級距，避免模型給出假精確。
- **允許自主，但設限。** 當資料顯示出重要主題時，模型可以新增小節，但必須沿用相同格式，並以小節結論收尾。
- **明確化解互相衝突的指引。** 當產業角度和公司發展階段有衝突時（例如高成長公司該用本益比還是股價營收比 P/S），prompt 會告訴模型如何取捨。

## 使用方式
替換 `{company_name}` 和 `{ticker}`，保留全域規則，並刪除所有產業框架，只留下符合該公司的一到兩套。搭配有網路搜尋或財務資料工具的模型效果最好，因為這份 prompt 要求引用來源、使用最新資料。
