# 可被證偽的投資組合研究：論點、有期限的訊號，以及對抗式審查

這是我個人的一套投資研究方法，目標是讓研究**能在某個日期被證明是錯的**。研究內容會整理成大約十條書面論點。每條論點都用「訊號」來檢驗：訊號是具體、有期限的押注，並事先寫好「什麼結果代表我錯了」。另外有一層 AI 審查，任務是攻擊這些論點，而不是附和。期限一到，就誠實評分，猜錯的也照樣記錄。

我在一個變化很快的產業上實際運作了好幾個月，由 Claude 負責每天的維護，Obsidian（一款筆記軟體）作為視覺化介面。本頁說明這套方法。真實的名稱、持股和研究內容都已刪除，所有範例都是虛構的。

> **非投資建議。** 這是一套研究方法，內容不構成任何買進或賣出的建議。範例中的所有公司、數字和日期都是虛構的。

## 問題在哪裡

大多數投資研究不可能是錯的。它們會說「需求依然強勁」或「我們看到上行空間」。這種句子不論結果如何都說得通，所以你從中學不到任何東西。

我還有第二個問題。我讀很多大型投資銀行的研究報告（也就是「賣方」：發布研究報告來爭取交易業務的銀行）。這些報告很適合用來了解其他人怎麼想。但它們天生就偏多，而且當四家銀行看法一致時，那只是一個擁擠的共識，不是四份證據。

第三個問題，是我開始和 AI 助理合作後才出現的：**AI 模型喜歡附和你。** 如果你有很強的觀點，模型會想辦法把每個新數據都解讀成支持你的證據。這種感覺很好，但毫無價值。

所以我想要一套系統，做到：

1. 每個看法都寫成可能失敗的形式。
2. 每次檢驗都有日期。
3. 流程中有某個角色的工作就是反對我。
4. 誠實記分，包括我錯的時候。

## 方法步驟

### 步驟 1：把研究整理成大約十條可被證偽的論點

**論點**是對市場某部分如何運作的看法，寫法必須讓它有可能被證明是錯的。「晶片股會表現很好」不是論點。「短缺正沿著供應鏈往下游移動，從晶片封裝到電路板再到測試，每個環節輪流取得定價權」才是論點，因為你可以檢查下一個環節是否真的取得了定價權。

我把數量控制在十條左右。再多，就沒辦法持續追蹤了。

每條論點包含：
- **一句話的核心主張。**
- **因果鏈**：主張成立所需的每個步驟（「A 導致 B，B 導致 C」）。每一步都是一個假設，而每個假設都可能失效。
- **推翻條件**：什麼情況下我會放棄這條論點。一個不可能失敗的故事，不允許成為高信心論點。
- **兩個獨立的評等。** *信心*（證據有多強？）和*狀態*（待驗證、已驗證、有爭議、已證偽）分開追蹤。一條論點可能證據很強，但還沒被檢驗過。

請見 [`thesis-template.md`](thesis-template.md)。

### 步驟 2：為論點配上有期限、事先寫好「什麼代表我錯了」的訊號

**訊號**是一個具體、有日期的押注，用來檢驗論點的某一部分。每個訊號都必須有：
- **一句話的主張。**
- **觸發條件**，分三種結果，並在證據出現*之前*寫好：
  - **已驗證**：押注成真（並寫明確切門檻），
  - **已證偽**：押注失敗（並寫明確切門檻），
  - **有爭議**：證據無法下定論（並寫明那會是什麼樣子）。
- **與真實事件綁定的期限**，也就是會給出答案的事件：財報、每月貿易數據公布、定價季。「年底前」很弱。「10 月 31 日第三季法說會前」就很明確。
- **資料來源。** 如果我知道該看什麼，卻沒有管道取得，訊號裡就要直接寫明（「已知缺口：無資料來源」）。一個有期限卻沒有東西可看的訊號，只是佔位置、假裝有在追蹤。

期限比什麼都重要。**沒有期限的押注永遠不會結案，也就永遠不會回頭修正你該有多少信心。**

請見 [`signal-template.md`](signal-template.md)。

### 步驟 3：進行對抗式審查，並設下「不要奉承我」的規則

論點之上有一層**審查層**，它的工作是找出弱點。我用 Claude 來執行，第一條規則用我自己的話說就是：*「不要為了讓我開心而調整你的結論。」*

審查會對每條論點問六個問題：

1. **重建因果模型。** 因果鏈的每一步都寫下來了嗎？每個箭頭背後都有假設嗎？
2. **檢查假設。** 哪些假設沒有訊號在追蹤？哪些訊號已經過期？
3. **檢驗證據。** 支持的證據是彼此獨立的，還是同一個來源重複出現？反對的證據有被公平看待嗎？
4. **找出矛盾。** 不利於論點的證據是否被悄悄降低權重？有沒有數據被反過來解讀？
5. **追蹤連鎖影響。** 如果某個假設失效，還有什麼會跟著崩壞？誰會受益、誰會受損？
6. **設計缺少的檢驗。** 哪些訊號應該存在卻還沒有？目前的期限合理嗎？

**硬性規則：審查只能提出建議。** 它可以建議新的假設、新的訊號或新的權重，但絕不能直接更改論點狀態或修改證據。所有變更都要經過步驟 4 的正常評分流程。這樣可以避免一個有說服力的論述，在沒有經過檢驗的情況下改寫紀錄。

審查也遵守一套簡短的紀律，因為少了它，審查就會變成「換句話把論點再講一遍」：

- **絕不說「這證實了你的看法」。** 附和一個很強的既有觀點，等於拿掉第二意見唯一的價值。如果你同意，要獨立說明理由。
- **銀行共識不是證據。** 好幾家帶著相同先天偏誤的銀行意見一致，只是一個擁擠的故事。要打折看待，不要重複計算。
- **如果 X 和非 X 都「支持」論點，就停下來。** 舉例：資金*流入*某個產業被解讀為「需求強勁，論點成立」，資金*流出*又被解讀為「健康的清洗，論點成立」。一個不管觀察到什麼都成立的結論，根本沒有被檢驗。要把每個數據歸到它真正能區分的情境，否則就標註「無法區分」。
- **也不要為了討好而翻轉立場。** 被質疑時（「你是不是只是在附和我？」），要修正推理，而不是為了顯得獨立就跳到相反的結論。
- **不准憑空捏造機率。** 只有能說出數字從哪裡來、有多確定時，才可以給數字。如果市場上有針對這個問題的真實價格（例如期貨對利率決策的定價），就用市場的數字，而不是直覺。如果事情已經發生，就當事實陳述，而不是給機率。如果沒有任何市場定價，就給方向、寬區間和「低信心」，絕不給看起來很精確的小數。
- **主動要最新數字。** 網路搜尋對變化快的數據會有落差，容易抓到聳動的標題，卻漏掉悄悄的反轉。最近一兩天的數據，要請人提供即時數字。

每次審查後，AI 會做一份七項自我檢查：我有沒有說「這證實了你的看法」？我有沒有把銀行共識當成證據？有沒有哪個數據我不管結果如何都解讀成支持？我引用的資金流向數據真的能區分不同情境嗎？每個機率我都能說出來源嗎？我是不是只因為被質疑就換邊站？最近兩天的數字我查了嗎，或有沒有開口要？

### 步驟 4：期限到了，誠實替自己評分

訊號期限一到，就評為**已驗證**、**已證偽**或**有爭議**，結果再回饋到論點：

```
已驗證    -> 論點信心上升
已證偽    -> 論點信心下降；
             若打到核心假設，論點狀態改為「已證偽」
有爭議    -> 無法判定；延長期限，並且寫下無法判定的原因
```

讓評分保持誠實的規則：

- **先評即將到期的訊號**，再讀任何新研究。否則新故事會把舊押注擠掉。
- **先讀主張，再看門檻。** 有些訊號刻意設計成違反直覺。如果主張是「銀行會拒絕承認 X」，那銀行承認 X 就代表訊號*已證偽*，即使聽起來像好消息。不要憑感覺評分。
- **比賽進行中不准移動球門。** 門檻可以在觀察期開始前或結束後修改，但不能在期間內修改。如果期間內發現門檻設計得很差，就直接說出來，照原本的門檻評分，再另開一個門檻更好的新訊號。
- **「優於預期」需要參考線。** 一家公司可能優於公開的分析師平均預估，卻仍然不如投資人私下的期待。股價反映的是第二個數字。任何沒說明是對照哪條線的「優於」或「低於」預期，權重都要降低。
- **股價變動不算讀數。** 門檻針對的是經營上的事實（合約價格、產能數字），而不是股價有沒有上漲。
- **答對不代表推理正確。** 每個結案的訊號都要寫成一則**發現**（發生了什麼、我學到什麼）。這些發現就是校準紀錄。

評分也會產生一本**錯題本**：記錄我自己的判斷被打敗的每一次。每一筆都寫下我錯在哪裡，以及我因此改了哪條規則。例如，只要某個結果有市場價格可參考，我現在就用市場價格，而不用自己的估計。

### 步驟 5：貫穿全局的三個觀念

**反向確認和確認一樣有價值。** 資訊量最大的數據，是和你目前判讀相反的那一個。如果股市重挫，但匯率依然穩住，就表示這大概不是資金外逃。我會主動去找這類數據。

**太早 ≠ 錯。** 對基本面判斷正確、只是時機太早，這是*時機成本*，不是論點失敗。一個創紀錄的季度之後股價卻下跌，可能代表「獲利見頂、評價倍數偏低」（評價倍數就是投資人為每一元獲利付出的價格），而不是「基本面壞了」。一定要說清楚是哪一層在變：基本面、評價倍數，還是時機。我把這些分開評分：方向、時機和投資組合策略各有各的成績。

**交易的另一邊是誰？** 每筆交易都有買方和賣方。價格*怎麼*變動，往往比變動*多少*更重要。一次逼使借錢買股的人賣出的崩跌，會把風險清掉；一次救了他們的急彈，則把風險留在原處。兩者在線圖上可能看起來一模一樣。

## 在 Obsidian 中如何組織

Obsidian 是一款免費的筆記軟體，把筆記存成純文字檔，並畫出彼此之間的連結。我把它當作**視覺化介面**：Claude 負責撰寫和更新筆記，我負責閱讀、點連結、看關係圖。

**五種筆記，絕不混用：**

| 筆記類型 | 內容 | 範例名稱（虛構） |
|:---|:---|:---|
| **證據（Evidence）** | 一個已發生的事實，附來源和品質評等。只寫一次，再從所有相關論點連結過來。 | `E07 Cloud Provider Raises Spending Plan` |
| **訊號（Signal）** | 一個有日期、可被證偽、設有三種結果門檻的押注。 | `S14 Board Supplier Price Increase Sticks` |
| **論點（Thesis）** | 由假設和證據構成的看法，附推翻條件。 | `T3 Shortage Moves Downstream` |
| **因子（Factor）** | 可以跨公司比較的驅動因素（例如「記憶體晶片吃緊程度」）。有狀態，但沒有對錯。 | `Factor Board` 上的一列 |
| **世界狀態（World State）** | 某個日期的整體市場背景快照。 | `World State 2026-Q3` |

另外還有三種輔助類型：**審查（Audit）**筆記（對抗式審查的產出）、**發現（Finding）**筆記（結案訊號的心得），以及**變更紀錄（Change Log）**（每天改了什麼、為什麼改）。

**架構強制執行的紅線：** 意見不是證據；假設不是主張；因子不是論點；模擬不是事實；決策不是論點；部位大小不是信念強度；結果正確不是推理正確。

**為什麼證據要獨立成筆記：** 一個事實（例如某家大型雲端業者上調支出計畫）可能同時影響四條論點。寫一次、連結四次，就能確保這個事實不會因為複製而前後不一致，也能看出有多少論點建立在它上面。

**為什麼因子要有自己的看板：** 把驅動因素從論點中抽出來，就能看出**隱藏的集中度**：「我十條論點中有四條，其實是押同一個變數。」每個因子列最後都有一個 `next_signal` 欄位，指向下一個能告訴你這個因子新資訊的訊號。

**命名與連結：** 論點命名為 `T<n> <Slug>`，訊號命名為 `S<nn> <Slug>`，slug（簡短識別名稱）一旦建立就不再更改。所有東西都用 `[[雙中括號]]` 連結。連到一則還不存在的筆記是刻意的：代表那是還沒完成的工作。

**絕不放進筆記庫的東西：** 個人持倉、進出場價格，以及買賣決策。這些完全不進檔案。筆記庫裡放的是研究，不是交易帳本。

**每日流程**由排程的 Claude 工作執行，順序固定：

1. 評分今天到期的訊號。
2. 把當天研究中每個新出現的分歧，轉成一個新訊號，期限綁定下一個能給出答案的事件。
3. 更新因子看板。
4. 只有在證據真的有變動時，才調整論點的信心。
5. 寫變更紀錄。如果沒有實質變化，就寫一行說明。不要捏造活動。

資料夾架構圖，以及一個事實如何透過連結層層擴散的範例，請見 [`obsidian-structure.md`](obsidian-structure.md)。

## 實際運作後學到的事

- **期限就是全部的關鍵。** 大部分的價值，來自被迫寫下「在這個日期之前、達到這個數字，否則我就錯了」。
- **「有爭議」也是一個真正的答案。** 有好幾個訊號在期限當天無法判定。寫下*原因*（數據沒公布、門檻有歧義），讓下一個訊號設計得更好。
- **審查最常抓到我的時候，是我在附和自己的時候。** 我記錄過最嚴重的錯誤，是在一個嚇人的數據出來後，馬上把自己的門檻往保守方向放寬。當時感覺像是謹慎。結果照原本寫好的門檻評分，原本的門檻才是對的。這件事現在已經是一條硬性規則（見 `market-thesis-skill.md`）。
- **AI 要成為好的對手，前提是你要明確地、用文字要求它這麼做，並用清單檢查它。**
