# 每天發文、還會自己查核事實的 AI 內容引擎

**這是什麼：** 我為一個 AI 理財助理（消費型個人理財 App）設計的系統。AI agent 撰寫英文和繁體中文的深度文章。每篇文章要先通過一連串檢查，最後由真人核准。接著排程器每天發布一篇，如果發布中斷，健康檢查會發出警報。

**我的角色：** 我制定內容策略、設計各道關卡和寫作規則，並用 AI 程式開發工具（Claude Code）建立和運作整條流程。AI agent 負責起草和檢查，真人編輯做最後的語氣檢查。網站和內容管理系統由公司的工程師負責。

## 1. 問題：AI 讓內容變便宜，而 Google 不再獎勵便宜的內容

AI 產品最直覺的做法是大量發文：由 AI 撰寫、多種語言的每日市場新聞。我們一開始試過類似的做法，學到三件事。

**新聞的壽命短，搜尋價值低。** 一則新聞只會被讀一天。大型新聞媒體早已佔據這些搜尋。小網站的新聞很少能排上名次，一週後幾乎沒人點。

**深度文章會持續帶來訪客。** 一篇完整回答大家反覆在問的問題的指南（「存款放多少現金算太多？」）可以透過搜尋被找到好幾個月。在我們的競品研究中，一個大型個人理財網站在兩年內失去了大部分較弱、排名較低的頁面，但它排在前 3 名的頁面卻增加了。結論是：大量單薄的長尾文章會被清掉。數量較少、但更深入、能排進前 3 名或被 Google AI 回答引用的文章，才能長久。

**機器翻譯會被視為重複內容。** 我們不再發布單純的機器翻譯。讀起來就像 Google 翻譯的產出，而 Google 會把近似複製的內容視為低價值。每種語言都必須以母語重新撰寫（見第 3 節）。

所以目標從「發更多」變成**「每天發一篇值得排上名次的文章，而且絕不發錯誤的文章」。**

## 2. 流程：上線前的五道關卡

每篇文章依序通過這些關卡。沒通過就退回，絕不跳關。

```
 草稿  ->  品質評分  ->  連結檢查  ->  事實查核 agent  ->  真人核准
                                                                |
                    健康檢查  <-  排程發布  <-----------------------+
                    （發布中斷時發出警報）
```

| 關卡 | 做什麼 | 為什麼需要 |
|---|---|---|
| **0. 草稿** | AI agent 依照固定規則撰寫：前約 200 字內回答問題、不寫空泛的填充內容、有幫助時放表格、一個連到對應主題中心頁的連結、文末一次低調的產品提及 | 規則勝過「幫我寫一篇文章」。這個資料夾裡的寫作 skill 就是一個例子。 |
| **1. 品質評分** | 自動審查員以 100 分為滿分評分（內容、SEO、可信度、技術設定、被 AI 搜尋引用的程度），並估算它有多「像 AI 寫的」。通過門檻：**85 分以上、沒有重大問題、AI 痕跡低。** | 在真人花時間之前，先抓出內容單薄、頁面設定缺漏和機械化的用語。 |
| **2. 連結檢查** | 每個連結都會被打開，必須載入真正的頁面。連結指向最終網址，讓讀者不必經過層層轉址。 | 財經文章裡的一個失效連結就會損失信任。見下方「soft 404」的教訓。 |
| **3. 事實查核 agent** | 另一個獨立 agent 把**每個數字、日期和價格**追溯到它實際打開過的來源，並檢查法遵紅線（詳見下方）。 | 不論是人還是 AI，寫手都不擅長檢查自己的作品。 |
| **4. 真人核准** | 由母語編輯閱讀每種語言的版本，檢查語氣。**絕不省略。** | 自動化關卡只是過濾器，最後由人做決定。 |

評分門檻設定得很誠實。評分器會獎勵統計數字很多的文章，我們**豁免**了這一項，因為為了達到統計數字的配額，最後就會捏造數字。少一點真數字，勝過多一點假數字。

**法遵紅線**（這是金融產品，所以這些等同法律規範，不是風格選擇）：
- 絕不把產品描述成顧問。它讀取你的帳戶、呈現並標記資訊，但不提供建議。
- 不給買進、賣出或持有的指示。不點名某檔基金或股票作為該買的標的。
- 不拿真實公司當作糟糕投資的例子。
- 每個數字都有來源和日期。

## 3. 兩種語言，以母語撰寫，不是翻譯

每篇文章都有英文版，以及寫給香港讀者的正式書面繁體中文版。中文版是**以母語重新撰寫**：

- 標題、小標和開頭，都是圍繞香港讀者實際會在 Google 輸入的字詞重新設計，不是從英文翻過來。
- 每個統計數字完全保持一致。美國的數據就標明是美國數據。**我們絕不為美國的數字捏造一個香港版本。**
- 讀者本來就用英文稱呼的品牌名稱、股票代號和術語，保留英文。
- 只跟美國有關的主題（美國稅務規定、只在美國提供的產品）完全不出中文版。寫一篇香港讀者用不到的產品的中文文章，對誰都沒有幫助。
- 最後由香港本地人閱讀，因為「正確」和「聽起來道地」是兩種不同的檢驗。

## 4. 最大的教訓：AI agent 會編出讀起來天衣無縫的統計數字

這是我最希望每個把 AI 用在公開發布內容的團隊都聽到的部分。

在我們研究型文章流程的壓力測試中，審查步驟抓到了捏造的數字：看起來合理的百分比、報酬率和數量，卻沒有任何真實來源。它們看起來一點都不像錯的：小數位數正確、放在通順的句子裡、也符合你的預期。這正是危險所在。**捏造的統計數字看起來不像捏造的。**

我們做了這些改變：

1. **每個數字都需要 agent 實際打開過、附有日期的來源。** 「憑記憶」的數字不算，沒點進去的搜尋結果摘要也不算。如果無法查證，該段落就不寫那個數字。
2. **先假設你的 agent 捏造了某些東西，** 直到第二個 agent 追溯查證過為止。
3. **一個錯誤的數字比沒有文章更糟。** 讀者搜尋一次就能推翻它，Google 的品質系統也會注意到前後不一致。
4. **用一個來源信任階梯**決定什麼算是來源：

```
  最可信
    1. 第一手來源：政府和監管機關網頁（稅務機關、
       勞動統計、證券監管機關）、公司申報文件、
       公司自己的價格頁面
    2. 有公信力的財經媒體
    3. 評論彙整網站和內容農場  ->  任何數字都絕不採用
  最不可信
```

當第一手來源擋住自動化存取時，agent 會找另一條路取得同樣的第一手資料，通常是官方的資料 API，而不是退而求其次去用二手網站。

這個資料夾裡的寫作 skill 把這一點內建為 **Zero Fabrication Rule（零捏造規則）**：
- 固定不變的事實（某款晶片公布的規格、某條法律何時通過）可以引用已知來源，並註明出處。
- 任何會變動的東西（價格、估值、分析師說法）**必須**在當次作業中查證。
- 沒有查證，就沒有數字。

## 5. 維持運作：流程壞掉時必須告訴你

每日排程只有在你知道它何時停止時才有用。三次真實的故障形塑了這個設計（詳見 [`publishing-pipeline-design.md`](publishing-pipeline-design.md)）：

- **「活著」不等於「有在運作」。** 最初的健康檢查只確認程式有執行，所以一篇卡住的文章可能讓發布停擺，健康紀錄卻還寫著「活著」。修正方式：健康檢查現在會問「過去兩天內真的有發布任何東西嗎？」如果沒有，就跳出桌面警示，並在大家看得到的地方留下一個警告檔案。
- **網站對不存在的頁面回應「OK」。** 即使文章不存在，網站也會回傳成功狀態碼（一種「soft 404」：它會悄悄顯示一般的文章列表頁）。檢查狀態碼什麼都證明不了。現在我們檢查頁面上是否顯示**這篇文章自己的標題**。
- **一篇有問題的文章可能卡住整個佇列。** 現在連續失敗三次的文章會被標為「失敗」並跳過。佇列繼續往下走，同時通知真人處理。

## 6. 心得

1. **在放大寫作量之前，先設計好關卡。** 生成文字是便宜的部分，檢查才是成本和風險所在。
2. **讓 AI 的產出容易查證，而不只是聽起來很好。** 內文附來源和信任階梯，把「看起來對」變成「查過了」。
3. **絕不讓品質分數逼寫手捏造東西。** 我們刻意關掉了「更多統計數字」的獎勵。
4. **對抗範本的指紋。** 我們稽核早期的 AI 新聞文章時，發現幾乎全部用同一套骨架。讀者和搜尋引擎都看得出來。寫作 skill 現在會強制結構多樣化：把同一個頻道的五篇文章攤開來，你應該猜不到第六篇長什麼樣。
5. **為每個市場重寫，不要翻譯。** 機器翻譯增加了頁數，卻沒有增加價值。
6. **監控結果，而不是過程。** 檢查文章有沒有上線，而不是程式有沒有執行。
7. **最後一關一定要有真人。** agent 是過濾器，不是編輯。
8. **穩定勝過爆量。** 每天一篇，天天如此。停擺之後，我們不會一口氣補發積壓的文章。錯過的日子就算了，讓網站永遠不會看起來像內容農場。
